# 🧭 检查路由配置

**只报告不修改**。新建页面后最常见的两类问题：忘注册路由、`meta.permission` 写错或漏写——本命令一键体检。

> 🎯 适用场景：跑完 `/新建Web页面` 后的事后体检 / PR 前对路由层做最后一道关卡 / 排查"页面写好了但侧边栏不显示"类问题。

## 📋 执行流程

| 步骤 | 操作 | 必须 |
|-----|------|-----|
| 1️⃣ | 在 `web/` 目录执行 `npm run lint:route`（默认扫 `frontend/src/router`） | ✅ |
| 2️⃣ | 阅读输出——每条会标注：文件、行号、违规规则、修复建议 | ✅ |
| 3️⃣ | 对未注册路由的页面，在 [router/index.ts](/projects/helper/web/frontend/src/router/index.ts) 补充 `path/name/component/meta` | ✅ |
| 4️⃣ | 同步检查 `.cache/permission_metas.json` / `.cache/rbac.json` 中的 permission key 是否一致（参考 `/新建Web页面` 第 6️⃣ 步） | ✅ |
| 5️⃣ | 修完再跑一次确认零违规 | 推荐 |

## 🛠️ 标准调用

```bash
cd web

# 默认扫 frontend/src/router
npm run lint:route

# 指定目录（ts-node 直跑）

# ⚠️ 实验性自动修复（默认请勿使用，先 dry-run）

  .codebuddy/skills/helper-web-spec/scripts/check-route.ts web/frontend/src/router --dry-run --fix
```

## 🎯 检查规则（典型违规）

| 规则 | 含义 |
|------|------|
| 路由 `name` 与 `path` 不一致 | `name: 'user-list'` ↔ `path: '/users'` 命名不对齐 |
| 缺 `meta.permission` | 受保护路由没声明权限 key，会被认为"任何人可访问" |
| `component` 非懒加载 | 没用 `() => import(...)` 异步导入，影响首屏体积 |
| 路由 path 重复 | 多条路由指向同一个 path |
| 子路由 path 以 `/` 开头 | 嵌套路由的 path 应为相对路径，不带前导斜杠 |

## ⚠️ 工具盲区（AI 二次核对）

- **`.cache/*.json` 与 router 的一致性**工具看不到——本命令只查 `router/`，需结合 `/新建Web页面` 第 6️⃣ 步同步 `.cache/permission_metas.json` / `.cache/rbac.json`
- **动态注册的路由**（`router.addRoute()`）工具识别不到，请人工确认
- **重定向 redirect** 是否合理工具不判断

## ❌ 禁止
- 直接用 `--fix` 让工具自动改（实验性，路由结构错了不可逆）
- 修了 router 却忘改 `.cache/*.json`（页面写好但侧边栏不显示就是这个原因）
- 路由 name 用中文 / 空格（应该是 kebab-case 或 camelCase）

## 🔄 工具失败时的兜底

1. 检查 `web/node_modules/` 是否安装；如无则 `cd web && npm install`
2. 仍失败回退**手工巡检**：参考 `references/01-architecture-overview.md` 路由章节 + `references/07-cache-json-sync.md` 配置同步清单
