# 📚 整理导入顺序

**支持自动修复**（不像 `check-timer` / `check-route` 是实验性，本工具的 `--fix` 是稳定的）。按规范分组重排 `import` 语句：

```
1. vue 系（vue / vue-router / pinia ...）
2. 第三方库（axios / lodash / tdesign-vue-next ...）
3. 项目内（@/...）
4. 相对路径（./ ../）
5. 纯类型导入（import type ...）
```

> 🎯 适用场景：提交前一键过 / 大重构后导入混乱 / 与 `/修复Web规范` 配合做完整收尾。

## 📋 执行流程

| 步骤 | 操作 | 必须 |
|-----|------|-----|
| 1️⃣ | 确认 git 工作区干净（避免修复出错难以回滚） | ✅ |
| 2️⃣ | 先跑 dry-run：`cd web && npm run lint:import-order -- --dry-run --fix`，肉眼核对 diff | ✅ |
| 3️⃣ | 确认无误后实际修复：`npm run lint:import-order -- --fix` | ✅ |
| 4️⃣ | 跑 `cd web && npm run build`（或 `tsc --noEmit`）确认仍可编译 | ✅ |
| 5️⃣ | 跑 `/审查Web规范` 验证整体合规 | 推荐 |

## 🛠️ 标准调用

```bash
cd web

# ✅ 仅检查（无 --fix）
npm run lint:import-order

# ✅ 第 1 步：dry-run 预览（看 diff，不落盘）
npm run lint:import-order -- --dry-run --fix

# ✅ 第 2 步：实际修复
npm run lint:import-order -- --fix

# 指定目录（ts-node 直跑）
npx ts-node -P .codebuddy/skills/helper-web-spec/scripts/tsconfig.json \
  .codebuddy/skills/helper-web-spec/scripts/check-import-order.ts web/frontend/src/views --fix
```

## 🎯 分组规则（IMPORT_ORDER）

| 序号 | 类别 | 识别特征 | 示例 |
|------|------|----------|------|
| 1 | `vue` | `vue` / `vue-router` / `pinia` 起手 | `import { ref } from 'vue';` |
| 2 | `third-party` | 不带 `@/`、不带 `./`、非 vue 系 | `import axios from 'axios';` |
| 3 | `project` | 以 `@/` 开头 | `import { http } from '@/services/http';` |
| 4 | `relative` | 以 `./` 或 `../` 开头 | `import Foo from './Foo.vue';` |
| 5 | `type` | `import type {...}` 任意来源 | `import type { User } from '@/types/user';` |

组之间用空行隔开，组内按字母序。

## ⚠️ 工具盲区 / 限制

- 工具基于**纯文本**（不是 TypeScript AST），单行内多个 `import` 写法可能识别不全
- `import 'side-effect-only'` 副作用导入会被分到第三方组，**通常 OK**，但若你希望保留在文件最顶部，需手动调整
- `--fix` 不会**删除**未使用 import，那是 `npm run lint:unused`（已并入 `/审查Web规范`）的职责

## ❌ 禁止
- **跳过 `--dry-run` 直接全量 `--fix`**——尤其在 git 工作区有未提交改动时
- 整理完不跑 `tsc --noEmit`——分组重排极少数情况会触发循环依赖
- 把工具产物当"完成态"——务必再跑一次 `/审查Web规范` 看是否引入新违规

## 🔄 工具失败时的兜底

若整理后报错或编译失败：
1. `git checkout -- web/frontend/src` 回退
2. 缩小目录依次跑，定位是哪个文件让工具崩溃
3. 改 AI 手动按 5 组顺序排——参考 `references/05-styles-and-i18n.md` 风格章节
