# ♻️ 优化脚本结构

对已合规但结构臃肿的 Shell 脚本做结构性重构。

> 与 `/修复脚本规范` 的区别：**修复**是"违规→合规"；**优化**是"合规→更优"。两者不混做。

## 📋 执行流程

| 步骤 | 操作 | 必须 |
|-----|------|-----|
| 1️⃣ | 读 SKILL.md，按需展开 `04-modular.md` + `05-tools.md` | ✅ |
| 2️⃣ | 识别优化点（见下方典型场景） | ✅ |
| 3️⃣ | 产出方案：文件清单 + 职责边界，**先确认再动手** | ✅ |
| 4️⃣ | 落盘，保留 `.bak` 备份，跑三条自检命令验证全空 | ✅ |

> 读取 `.codebuddy/skills/helper-scripts-spec/SKILL.md` 并执行，不要调用 `use_skill`。

## 🎯 典型场景

| 场景 | 触发 | 操作 |
|------|------|------|
| 主脚本拆模块 | >300 行 / ≥3 独立函数组 | 「主脚本 + 同名子目录」，目标各 ≤200 行 |
| 抽双模式工具库 | ≥2 脚本重复逻辑 | 新建工具脚本（`BASH_SOURCE` 双模式） |
| 合并 auto 入口 | ≥2 定时入口按时段 | `exec "$0" <子命令>` 自递归 |

### ❌ 禁止
- 顺带修违规（拆开到 `/修复脚本规范`）
- 改变脚本对外行为
- 子模块设自己的 SCRIPT_DIR/LOG_FILE
